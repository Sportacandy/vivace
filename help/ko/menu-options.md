# 옵션

**옵션** 메뉴에는 환경 설정과 인터페이스 구성이 있습니다.

- **환경 설정…**(`Ctrl+P`) — 주 설정 대화상자: 일반, 인터페이스, 자막, 키보드 및
  마우스, 재생 목록, 드라이브, TV, 파일 형식, 업데이트, 네트워크, 고급. 변경 사항은
  즉시 적용되며 **취소** 는 되돌립니다.
  - **네트워크** 에는 OpenSubtitles, YouTube, 프록시, 전송 탭이 있습니다.
    **프록시** 탭에서는 선택적 HTTP 또는 SOCKS5 프록시를 앱 전체에 적용할 수
    있습니다(OpenSubtitles 검색, 업데이트 확인, 그리고 HTTP인 경우에만 미디어
    재생과 yt-dlp). **전송** 탭은 *재생 ▸ 다음으로 전송 ▸ 스마트폰/태블릿* 이
    수신 대기하는 포트를 고정합니다. 이제 OpenSubtitles 계정 비밀번호와
    프록시 비밀번호는 Vivace 자체 설정이 아니라 운영체제의 자격 증명
    관리자에 안전하게 저장됩니다.
- **시스템 트레이에 아이콘 표시** — Vivace를 트레이에서 접근할 수 있게 유지합니다.
- **도구 모음**
  - **도구 모음** / **컨트롤 바** — 각 막대를 표시하거나 숨깁니다.
  - **주 도구 모음 편집…** / **컨트롤 바 편집…** — 표시할 버튼과 순서, 아이콘 크기를 선택합니다.
- **상태 표시줄**
  - **상태 표시줄 표시** 및 표시 내용: **영상 정보**, **오디오 정보**, **형식 정보**,
    **비트레이트 정보**, **프레임 카운터**, **전체 시간 표시**, **남은 시간 표시**,
    **현재 시간을 밀리초로 표시**.

**팁:** 전체 레이아웃(Basic / Mini / MPC)은 *환경 설정 ▸ 인터페이스* 에서 선택합니다.

## yt-dlp 설치 및 업데이트

*환경 설정 ▸ 네트워크 ▸ YouTube* 에는 Vivace가 YouTube 링크 재생에
사용하는 `yt-dlp` 프로그램을 어떻게 가져오고 유지 관리할지 제어하는
**관리되는 yt-dlp 사용** 확인란이 있습니다.

- **켬**(기본값) — Vivace가 `yt-dlp` 를 대신 설치하고 최신 상태로
  유지할 수 있습니다. **yt-dlp 경로:** 필드는 Vivace 자체 관리 복사본에
  고정되어 직접 편집할 수 없습니다. 최신 공식 릴리스를 받고 싶을
  때마다 확인란 옆에 있는 **yt-dlp 설치/업데이트…** 버튼을 사용하세요.
  **yt-dlp 자동 업데이트:** 설정도 함께 사용할 수 있게 되어, Vivace가
  스스로 이 업데이트를 실행하게 할 수 있습니다 — **하지 않음**,
  **yt-dlp를 실행할 때마다**, **하루에 한 번** 또는 **일주일에 한 번**
  중에서 선택합니다. 자동 업데이트는 실제로 YouTube URL을 해석하거나
  다운로드하기 직전에 실행되므로, 업데이트가 필요해진 뒤 첫 재생은
  약간 더 오래 걸립니다. 업데이트 자체가 실패하면(예: 네트워크 없음)
  Vivace는 재생을 막지 않고 이미 설치된 버전으로 조용히 계속
  진행합니다.
- **끔** — `pip` 나 운영체제의 패키지 관리자 등으로 직접 관리하는
  yt-dlp를 위한 설정입니다. **yt-dlp 경로:** 필드가 편집 가능해져서
  해당 복사본을 지정할 수 있고, **yt-dlp 자동 업데이트** 는
  비활성화됩니다 — Vivace는 자신이 관리하지 않는 yt-dlp를 절대
  설치하거나 업데이트하지 않습니다. 이 모드에서는 **yt-dlp
  설치/업데이트…** 버튼도 비활성화됩니다.

## YouTube 다운로드용 쿠키 내보내기

**쿠키 파일:** 필드(*환경 설정 ▸ 네트워크 ▸ YouTube*)를 사용하면
**다운로드 후 재생** 및 **외부 도구** YouTube 모드가 마치 로그인한 것처럼
동작하게 할 수 있습니다 — 연령 제한, 회원 전용 또는 그 밖의 계정 인증이
필요한 동영상에 필요하며, 전체 HD/4K 다운로드를 여는 열쇠이기도 합니다.
이 필드에는 일반 텍스트 `cookies.txt` 파일이 필요하며, 고전적인 Netscape
쿠키 저장 형식(yt-dlp 자체의 `--cookies` 옵션이 읽는 것과 동일한 형식)이어야
합니다. Vivace는 브라우저 프로필에서 직접 쿠키를 읽지 않습니다.

**만드는 방법:**

1. 사용하려는 접근 권한을 가진 계정으로 평소 사용하는 브라우저에서
   youtube.com에 로그인합니다.
2. Netscape 형식으로 내보내는 쿠키 내보내기 브라우저 확장 프로그램을
   설치합니다 — Chrome, Edge 또는 Brave의 경우 브라우저 확장 프로그램
   스토어에서 "Get cookies.txt"와 같은 것을 검색하고, Firefox의 경우
   "cookies.txt"를 검색하세요. 고전적인 Netscape `cookies.txt` 형식으로
   내보낸다고 명확히 밝힌 확장 프로그램이라면 무엇이든 사용할 수 있습니다.
3. youtube.com 탭을 연 상태에서 확장 프로그램을 사용하여 해당 사이트의
   쿠키를 내보내고, 결과를 디스크의 어딘가에 `.txt` 파일로 저장합니다.
4. Vivace에서 *환경 설정 ▸ 네트워크 ▸ YouTube* 를 열고 **쿠키 파일:** 옆의
   **찾아보기…** 를 사용하여 해당 파일을 선택합니다.

**참고 사항:**

- `cookies.txt` 파일은 사실상 저장된 로그인 세션입니다 — 이 파일을 가진
  사람은 누구나 쿠키가 만료되거나 로그아웃할 때까지 당신의 YouTube 계정
  처럼 행동할 수 있습니다. 다른 사람이 접근할 수 없는 곳에 보관하고
  공유하지 마세요.
- 쿠키는 **다운로드** 경로(다운로드 후 재생 / 외부 도구)에서만 사용됩니다.
  Vivace는 **스트리밍** 모드에서는 의도적으로 쿠키를 절대 전송하지
  않습니다 — 로그인된 스트림 URL은 Vivace의 단순한 동영상 재생기가 열 수
  없는 방식으로 해당 세션에 묶여 있기 때문에, 쿠키 파일이 설정되어 있어도
  스트리밍은 익명으로 유지됩니다.
- 쿠키는 만료됩니다. 이전에 잘 되던 다운로드가 실패하기 시작하거나 더
  낮은 화질/공개 버전 결과로 대체된다면, 새 `cookies.txt` 를 다시
  내보내세요.

## YouTube 다운로드용 ffmpeg 설치

**다운로드 후 재생** 모드는 yt-dlp가 다운로드한 별도의 동영상 스트림과
오디오 스트림을 하나의 재생 가능한 파일로 병합하기 위해 `ffmpeg` 가
필요합니다 — YouTube는 HD를 단일 결합 스트림으로 제공하는 경우가 드물어,
동영상 트랙과 오디오 트랙이 각각 다운로드된 다음 병합됩니다.
**ffmpeg 위치:** 필드(*환경 설정 ▸ 네트워크 ▸ YouTube ▸ 다운로드 후
재생*)는 yt-dlp에 그 위치를 알려줍니다. 비워두면 대신 시스템 PATH에 있는
`ffmpeg` 를 사용합니다.

**ffmpeg 설치 방법:**

1. **Windows** — 가장 쉬운 방법은 패키지 관리자를 사용하는 것입니다:
   `winget install ffmpeg`(또는 `scoop install ffmpeg` /
   `choco install ffmpeg`). 또는 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/)
   나 [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds) 에서
   미리 빌드된 압축 파일을 다운로드해 원하는 위치에 압축을 풀어도
   됩니다.
2. **macOS** — `brew install ffmpeg`(Homebrew).
3. **Linux** — 배포판의 패키지 관리자로 설치하세요. 예:
   `sudo apt install ffmpeg`(Debian/Ubuntu), `sudo dnf install ffmpeg`
   (Fedora), 또는 `sudo pacman -S ffmpeg`(Arch).
4. ffmpeg를 시스템 PATH에 추가했다면 **ffmpeg 위치:** 를 비워두세요.
   그렇지 않다면 `ffmpeg` 실행 파일 자체가 아니라, 그 실행 파일이 들어
   있는 *폴더* 의 경로를 해당 필드에 붙여넣으세요.
5. 설치 후 Vivace를 재시작하세요(또는 그냥 다운로드를 다시 시도해도
   됩니다).

**참고 사항:**

- 이것은 아래의 Deno와 마찬가지로 **yt-dlp** 의 의존성입니다 — Vivace는
  이를 외부 프로세스로 실행할 뿐입니다.
- **스트리밍** 모드는 이미 결합된 단일 스트림을 재생하므로 ffmpeg가
  전혀 필요하지 않습니다. ffmpeg가 필요한 것은 **다운로드 후 재생**
  뿐이며, 이 모드는 동영상과 오디오를 각각 가져와 로컬에서 병합하기
  때문입니다.
- 다운로드가 병합 관련 오류로 실패한다면 먼저 ffmpeg 위치를
  확인하세요 — Deno가 없거나 오래된 경우를 제외하면 가장 흔한
  원인입니다.

## YouTube 다운로드용 Deno 설치

Vivace뿐 아니라 yt-dlp 자체도, YouTube가 동영상의 실제 다운로드 URL을
내주기 전에 제시하는 문제를 해결하기 위해 별도의 외부 JavaScript
런타임을 사용합니다. yt-dlp 자체 문서에 따르면 런타임 없이 실행하는
것은 "지원 중단(deprecated)" 되었지만 완전히 실패하지는 않습니다 —
사용 가능한 형식이 단순히 줄어들 뿐이며, **로그인(쿠키) 요청의 경우
특히 심각하게** 줄어듭니다 — 이는 바로 **다운로드 후 재생** 모드가
HD, 회원 전용, 연령 제한 동영상의 잠금을 해제하기 위해 보내는 요청의
종류입니다. **스트리밍** 모드는 쿠키를 절대 보내지 않으므로(위의
"YouTube 다운로드용 쿠키 내보내기" 참조) 심각한 경우에 해당하지 않으며,
대부분의 경우 Deno 없이도 잘 작동합니다. 이것이 **Deno 경로:** 필드가
일반적인 YouTube 설정이 아니라 *환경 설정 ▸ 네트워크 ▸ YouTube ▸
다운로드 후 재생* 아래에 있는 이유입니다. yt-dlp는 여러 JS 런타임을
지원하며, Deno는 기본적으로 찾는 런타임입니다.

**Deno 설치 방법:**

1. 운영체제에 맞게
   [docs.deno.com](https://docs.deno.com/runtime/getting_started/installation/)
   의 공식 설치 안내를 따르세요(플랫폼에 따라 설치 스크립트 또는
   winget/scoop/Homebrew/apt 같은 패키지 관리자를 사용합니다).
2. `deno` 실행 파일이 시스템 PATH에 포함되도록 하세요 — 위의
   설치 프로그램은 보통 이를 자동으로 처리합니다. Windows에서는
   `denort`(다른 관련 실행 파일로, 여기서는 작동하지 않음)가 아니라
   `deno` 를 받았는지 확인하세요.
3. PATH를 수정하고 싶지 않다면 그대로 두고, 대신 전체 경로를
   **Deno 경로:**(*환경 설정 ▸ 네트워크 ▸ YouTube ▸ 다운로드 후
   재생*)에 붙여넣으세요.
4. 설치 후 Vivace를 재시작하세요(또는 그냥 다운로드를 다시 시도해도
   됩니다).

**참고 사항:**

- 이것은 Vivace 자체가 아니라 **yt-dlp** 의 의존성입니다 — Vivace는
  yt-dlp를 외부 프로세스로 실행할 뿐, Deno를 직접 호출하지 않습니다.
- yt-dlp는 비교적 최신 버전의 Deno를 필요로 합니다(이 글을 쓰는 시점
  기준 2.3.0 이상). 설치 후에도 다운로드에서 화질/형식 오류가 계속
  나타난다면 `deno --version` 을 확인하고 오래된 버전이면 업데이트
  하세요.
- 이 요구 사항은 Vivace가 아니라 YouTube/yt-dlp 쪽의 변경에서
  비롯됩니다 — 바로 이런 이유로 **Deno 경로:** 필드가 존재하며, Deno
  자체가 설치되어 접근 가능하기만 하면 추가 설정은 필요 없습니다.
